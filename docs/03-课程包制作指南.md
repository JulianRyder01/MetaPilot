# 课程包制作指南

> 每个课程是一个独立可分发、可导入/更新的包。本指南面向希望为 MetaPilot 制作课程的开发者。

## 1. 课程包结构

```
my-course/
├── manifest.json      # 课程元数据 + 完整内容（必需）
└── interactives/      # 动态交互块资产（可选，被 interactive 块引用）
    ├── convolution.html
    └── ...
```

打包为 `my-course.zip`（zip 内含 manifest.json）即可导入；也可以直接放置目录由后端 seed 脚本导入。

## 2. manifest.json 格式

```json
{
  "formatVersion": 1,
  "id": "digital-image-processing",
  "name": "数字图像处理",
  "author": "MetaPilot",
  "version": "1.0.0",
  "description": "课程简介",
  "library": { "name": "专业核心课", "description": "导入时自动建库（若未指定库）" },
  "collections": [
    {
      "name": "数字图像处理",
      "kind": "course",
      "description": "...",
      "documents": [
        {
          "name": "第1章 图像与数字化",
          "docType": "study",
          "sections": [
            {
              "name": "1.1 什么是数字图像",
              "blocks": [
                { "type": "markdown", "content": "## 标题\\n正文..." },
                { "type": "single_choice", "question": "...", "options": ["A", "B"], "answer": 0, "explanation": "..." },
                { "type": "interactive", "title": "卷积演示", "file": "interactives/convolution.html", "height": 560 }
              ]
            }
          ]
        }
      ]
    }
  ]
}
```

字段约定见 [docs/02-数据模型.md](02-数据模型.md)（块类型、字段）。

## 3. 动态交互块约定

- 每个交互块是一个**自包含的 HTML 文件**，放在 `interactives/` 下，被 `interactive` 块通过 `file` 引用。
- 运行环境：iframe `sandbox="allow-scripts allow-same-origin allow-forms allow-popups"`。
  - 可以使用内联 JS 与 CSS；推荐**零外部依赖**（自包含，离线可用）。
  - 不要使用 `localStorage` 等存储 API。
  - 建议带中文标题与说明文字，界面简洁。
- `height` 字段控制 iframe 初始高度（默认 480，v1.1.0 起默认自适应内容高度）。
- v1.1.0 起交互块支持**高度自由拖拽**（底部手柄）与**全屏**。

参考实现：`courses/demo-features/interactives/static_demo.html`（静态交互）、`courses/demo-features/interactives/quest.html` 与 `chat_demo.html`（动态交互）。

### 3.1 动态交互 HTML（mode="dynamic"）

`interactive` 块设 `mode: "dynamic"` 即动态交互模式，另可配：

| 字段 | 说明 |
|---|---|
| `multimodal` | 是否多模态模型。`false`（或缺省）时页面调用「添加图片」埋点会触发右上角提示「您配置的大模型不支持多模态输入」 |
| `scenario` | 情景设定（context prompt）：制作时写入，课程编辑页可改。AI 评判时依据它理解规则/评判标准/输出格式 |
| `lastResult` | AI 评判生成的 `{markdown, html}` 结果（保存于本块，重做交互覆盖旧结果） |

组件内的 HTML 通过 `window.parent.postMessage` 调用四个前端埋点接口（父页面校验来源）：

```js
// 1) 添加文本到评判上下文（用于最终评判，勿用于子对话）
window.parent.postMessage({ type: "metapilot:context:text", text: "系统：用户击杀一名敌人" }, "*");

// 2) 添加图片到评判上下文（data URL；multimodal=false 时父页面 toast 提示且不接收）
window.parent.postMessage({ type: "metapilot:context:image", dataUrl: "data:image/png;base64,..." }, "*");

// 3) AI 生成文本（子对话场景；前端自行维护 context json，随请求发送；异步回传结果）
window.parent.postMessage({
  type: "metapilot:generate:text", requestId: "req-1",
  prompt: "请以客户身份回复我：……",
  context: ["user：你好", "assistant：您好，请问需要什么帮助？"]
}, "*");
// 监听回传：{ type: "metapilot:generate:result", requestId, text, ok, error? }

// 4) 结束并提交给 AI 评判（也可不调用，用户可点组件右下角按钮手动结束）
window.parent.postMessage({ type: "metapilot:finish" }, "*");
```

评判 AI 依据 `scenario` 情景设定与评判上下文（文本 + 图片），生成 **Markdown 与 HTML 双版本结果展示页**（兼容渲染，HTML 可内嵌样式），保存于本交互块并可随时「查看结果」。

示例：`courses/demo-features/interactives/quest.html`（知识大闯关：击杀/通关/失败写入上下文、AI 求助、上传截图）、`chat_demo.html`（人机对话：前端维护 context json、发送图片触发多模态提示）。

## 4. 制作流程（推荐）

1. **规划**：按"基石优先 + 期末考点 + 真知识价值"组织章节（学习章节 `docType: study`）与测验章节（`docType: quiz`），学习/考试可自由分离。
2. **写内容**：用 `python` 脚本（参考 `backend/scripts/seed_dip.py`）以数据结构定义课程，便于复用 helper（`md/sc/mc/fb/sa/iv`）。
3. **做交互**：为每个核心知识点编写 `interactives/*.html`。
4. **生成并校验**：运行脚本生成 `manifest.json`，并检查所有 `interactive.file` 引用存在。
5. **导入**：客户端「库 → 导入 → 课程包」上传 zip；或指定库导入。
6. **更新**：再次导入同一 `id` 的课程包将替换旧版本（内容 + 资产），无需删除旧课。

## 5. 导入 / 导出

| 操作 | 方式 |
|---|---|
| 导入 zip | 客户端导入对话框，或 `POST /api/plugins/course/import`（multipart `file`，可选 `libraryId`） |
| 导入 md 笔记 | `POST /api/plugins/notes/import`（按二级标题自动分小节） |
| 导出课程 | 课程页「导出」按钮，或 `GET /api/plugins/course/{cid}/export`（返回 zip） |

## 6. 内容设计建议（对应本项目课程理念）

- **基石知识点**（如采样定理、卷积、傅里叶变换）必须配交互可视化，并单独成节。
- 每个知识点包含：`markdown` 讲解（含公式、期末考点提示）+ `interactive`（可视化）+ 1~2 个题目。
- 主观题（简答/填空）设置 `ai_graded: true`，由 MiniMax-M3 判分；`keywords` 与 `reference` 写得越明确，判分越准。
- 章节末尾可加"为什么值得留下"，说明该知识在工程/社会中的实际价值。
