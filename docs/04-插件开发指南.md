# MetaPilot 插件开发规范

> **规范版本：1.0.0**（本文档即规范本体，可持续更新，见 §0 版本与演进）
>
> MetaPilot 的功能以插件形式启用。插件分为三类：**官方核心**（MetaPilot 本身，不可禁用/删除）、
> **官方插件**（官方开发，可选用/禁用，不可删除）、**用户自定义插件**（可开发、禁用、删除）。
> 本文档规定插件的开发方式、目录结构、元数据 schema、路由约定与前后端接入机制，
> 是插件开发的**唯一权威约定**（此前为「插件开发指南」，v1.0 起升级为规范）。

---

## 0. 版本与演进

- 本规范使用语义化版本（`MAJOR.MINOR.PATCH`），当前为 **1.0.0**。
- **向后兼容承诺**：
  - `MINOR` / `PATCH` 升级只做**新增与澄清**，不删除或改变既有字段/约定的含义；
  - `MAJOR` 升级可调整约定，但必须在本章登记「迁移说明」，且**旧版插件在过渡期内仍可加载运行**（见 §9）；
  - `plugin.json` 的字段**只增不删**；新增字段一律可选，缺省时回退到旧行为。
- **「规范兼容」的含义**：按旧版规范编写的插件在新版规范下仍能正常加载与运行。
  它**不等于**「API 路径永远不变」——插件自身的 API 演进属插件内部事务（需前后端同步，见 §6）。
- 变更记录：每次更新本文档，在文末「附录：变更记录」追加一行（版本、日期、变更摘要）。

## 1. 插件是什么：前后端双插件模型

MetaPilot 是 **Web 应用（React SPA + FastAPI 后端）**。浏览器中的前端没有本地文件系统/进程能力，
所有数据（库、进度、统计、AI、文件读写）都在后端。因此插件的形态与 Obsidian / VS Code 这类
**桌面应用插件**（插件跑在客户端进程内，自己读写本地数据）不同，采用 Web 平台通行的
**前后端双插件**模式（Grafana / Jenkins / WordPress 同款）：

| 组成部分 | 位置 | 职责 | 必需性 |
|---|---|---|---|
| 后端插件 | `backend/plugins/<plugin_id>/`（Python 包） | 提供 `/api/plugins/<plugin_id>/...` 端点与业务服务（数据、AI、文件读写等） | **必需**（只要涉及新数据/服务） |
| 前端插件 | `client/src/plugins/<plugin_id>/`（注册模块） | 注册页面路由、导航入口与 API 客户端，渲染 UI 并调用后端端点 | **必需**（要让用户在前端看到功能） |

**一个插件 = 一个后端包 + 一个前端注册模块**，用同一个 `plugin_id` 绑定：

- 后端插件由加载器扫描 `backend/plugins/` 自动加载，`PluginManager` 管理启用/禁用状态（持久化于 `backend/data/plugins.json`）；
- 前端插件由注册表（`client/src/plugins/registry.ts`）统一收集，`App.tsx` / `AppLayout.tsx` 据此渲染路由与导航；
- **启用状态以后端为准**：前端通过 `GET /api/plugins` 感知，禁用时用 `PluginGate` 组件展示提示。

> 边界：只读核心数据的纯展示插件可以只写前端注册模块；但只要涉及**新数据、外部服务、AI、
> 文件读写或任何后端能力**，就必须同时提供后端插件。禁止在前端伪造数据（mock）冒充插件能力。

## 2. 插件分类

| 分类 | source | 可禁用 | 可删除 |
|---|---|---|---|
| 官方核心（MetaPilot 本身） | `core` | 否 | 否 |
| 官方插件 | `official` | 可 | 否 |
| 用户自定义插件 | `user` | 可 | 可（`DELETE /api/plugins/{id}` 物理删除） |

## 3. 后端插件骨架（plugin.json 为唯一元数据源）

```text
backend/plugins/my_plugin/
├── __init__.py      # 定义 Plugin 子类 + plugin 实例（只写 id 与 register）
├── plugin.json      # 元数据唯一来源（id/name/version/source/specVersion/...）
└── routes.py        # 路由（带门禁）
```

### 3.1 `__init__.py`：类只承担行为

元数据一律写在 `plugin.json`，**Python 类中不要重复声明**（消除双源漂移）：

```python
# backend/plugins/my_plugin/__init__.py
from fastapi import FastAPI
from app.plugins.base import Plugin

class MyPlugin(Plugin):
    id = "my_plugin"            # 仍保留 id 作为最小标识（与目录名一致）

    def register(self, app: FastAPI) -> None:
        from .routes import router
        app.state.my_plugin = MyService(...)   # 挂到 app.state 供路由取用
        app.include_router(router)

plugin = MyPlugin()
```

### 3.2 `plugin.json`：schema v1

```json
{
  "specVersion": "1.0",
  "id": "my_plugin",
  "name": "我的插件",
  "version": "1.0.0",
  "description": "插件做什么",
  "author": "你",
  "source": "user",
  "depends_on": []
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `specVersion` | 否（缺省视为 `1.0`） | 本插件遵循的规范版本；高于加载器支持版本时打印警告但**仍尝试加载**（宽松兼容，见 §9） |
| `id` | 是 | 小写下划线，全局唯一；**目录名 = id** |
| `name` / `version` / `description` / `author` | 是 | 展示用元数据；`version` 为插件自身语义化版本 |
| `source` | 是 | `core` / `official` / `user`（用户自定义默认） |
| `depends_on` | 否 | 依赖的其它插件 id 列表；启用前会检查依赖已启用 |

> 兼容说明：`plugin.json` 缺失或字段缺失时，加载器回退到 `Plugin` 类的默认属性
> （旧格式插件不写 `plugin.json` 也能加载，见 §9）。

### 3.3 启动与门禁

启动时 `app/plugins/loader.py` 扫描 `backend/plugins/` 目录自动加载，**无需修改 main.py**。
路由始终挂载，被禁用时由 `requires_plugin` 依赖返回 503 + 启用提示：

```python
# backend/plugins/my_plugin/routes.py
from fastapi import APIRouter, Depends
from app.plugins.base import requires_plugin

router = APIRouter(
    prefix="/api/plugins/my_plugin",
    tags=["my_plugin"],
    dependencies=[Depends(requires_plugin("my_plugin"))],
)
```

## 4. 后端路由约定（强制统一前缀）

- **所有插件路由统一挂载在 `/api/plugins/<plugin_id>/` 之下**，`plugin_id` 与目录名、`plugin.json` 的 `id` 三者一致。
- 一个插件可以在该前缀下挂多个子路由（如 `/api/plugins/course/progress`、`/api/plugins/course/ai`），
  但**不得**使用 `/api/<非插件命名空间>` 或与其它插件重叠的短前缀（如 `/api/kb`）。
- 每个路由都必须加 `requires_plugin("<plugin_id>")` 门禁。
- 插件不得占用核心命名空间（`/api/libraries`、`/api/collections`、`/api/documents`、`/api/sections`、
  `/api/blocks`、`/api/plugins`、`/api/health`、`/api/stats/core`、`/api/stats/widgets` 等核心路由）。

> 历史说明：v1.0 之前 course 插件曾使用 `/api/progress`、`/api/stats`、`/api/ai`、`/api/assets/courses`，
> knowledge_base 插件曾使用 `/api/plugins/kb` 短前缀；v1.0 起已全部迁入 `/api/plugins/<id>/` 统一前缀。

## 5. 访问核心能力

- `request.app.state.store`：`LibraryStore`，库/文档集/文档/小节/块 CRUD（见 `app/storage/store.py`）
- `request.app.state.progress` / `request.app.state.stats`：进度与统计（由 course 插件注册）
- `request.app.state.importer`：课程包导入/导出
- `request.app.state.kb`：知识库服务（KBService：索引/检索/问答）
- `app/services/ai_grader.py`、`app/services/minimax.py`：MiniMax 判题与通用 chat 调用
- `app/services/embedding.py`：本地 embedding provider（Qwen3-Embedding-0.6B）

插件把自己的服务挂到 `app.state.<plugin_id>`，路由经 `request.app.state` 取用；
插件间依赖通过 `depends_on` 声明，不直接 import 对方模块。

## 6. 前端插件注册表

前端插件以**注册模块**形式登记到注册表，由 `App.tsx` / `AppLayout.tsx` 统一读取渲染：

```text
client/src/plugins/
├── registry.ts        # 注册表：收集全部插件的前端注册信息
├── types.ts           # PluginFrontend 接口定义
├── course/            # course 插件：路由/导航/API 客户端
├── knowledge_base/    # knowledge_base 插件
├── themes/            # themes 插件
└── symlink/           # symlink 插件
```

每个插件注册模块导出：

- `routes`：插件页面的 `<Route>` 定义（页面组件放 `client/src/pages/` 或插件模块内）；
- `navItems`：插件贡献的顶栏导航项（`to` / `label` / `icon`）；
- `api`：插件后端端点的 API 客户端函数（真实调用 `/api/plugins/<plugin_id>/...`，**禁止 mock**）。

`App.tsx` 渲染核心路由 + 注册表收集的插件路由；`AppLayout.tsx` 渲染核心导航 + 插件导航。
插件启用状态由 `usePluginsStore`（`GET /api/plugins`）感知，禁用页面用 `PluginGate` 包裹。

## 8. 强制性开发规范清单

- 插件 id 使用小写下划线，全局唯一；**目录名 = `plugin.json` 的 `id` = 路由前缀中的 `<plugin_id>`**。
- 元数据**唯一来源是 `plugin.json`**；`__init__.py` 只写 `id` 与 `register`。
- `plugin.json` 必须声明 `specVersion`（新插件）与 `source`（core/official/user）。
- 路由前缀统一 `/api/plugins/<plugin_id>/`；每个路由加 `requires_plugin` 门禁。
- 用户插件可被 `DELETE /api/plugins/{id}` 删除（路径净化已内置）。
- 新插件必须写测试（`backend/tests/`，pytest + TestClient）；前端改动需 `tsc` 通过。
- 依赖写入 `backend/requirements.txt`，敏感配置走 `.env`（模板追加到 `.env.example`）。
- 完成一个功能点提交一次 commit（中文描述）。

## 9. 兼容性策略

- **旧插件无需改动即可加载**：`plugin.json` 缺 `specVersion` 视为 `1.0`；缺字段回退类属性；
  完全没有 `plugin.json` 的旧格式插件按类属性加载。
- **规范升级**：`MINOR`/`PATCH` 只增不删；`MAJOR` 变更须在本章追加迁移说明，并在过渡期
  保持旧字段缺省可用（宽松加载：`specVersion` 高于加载器支持版本时仅警告，不拒绝加载）。
- **API 路径演进**：插件自身 API 变更属插件内部事务，须后端与前端注册模块同步修改；
  如无特殊理由，保持 `/api/plugins/<id>/` 前缀稳定，避免破坏第三方客户端。
